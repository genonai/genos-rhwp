- **상태**: 복구안 승인, 정정 계획 승인 전 추가 구현 중지

## 1. 작업지시자 지적

> 하위이슈를 부모 이슈에 sub-issue로 등록하지 않아도 될까? 그리고 각각 이슈를 현재
> 하이퍼-워터폴을 준수하지 않고 진행한 것 같은데 정리할 수 있어?

지적은 두 가지다.

1. #3693과 #3695가 본문에서 #1528을 참조할 뿐 GitHub native sub-issue로 연결되지 않았다.
2. 전체 진행 순서 승인을 개별 수행·구현 계획 승인으로 잘못 해석해 승인 전 구현과 보고가 선행됐다.

## 3. 작업지시자 승인 복구안

1. #3693, #3695를 #1528의 native sub-issue로 순서대로 연결한다.
2. 기존 두 커밋은 삭제·amend·rebase하지 않고 사전 승인 WIP 증적으로 보존한다.
3. 계획서의 잘못된 승인 표기를 제거하고 WIP·승인대기 상태를 명시한다.
4. 기존 단계·최종 보고서는 확정 결과가 아닌 WIP 실측 기록으로 재분류한다.
5. 오늘할일과 GitHub 이슈 코멘트에 절차 복구 상태를 기록한다.
6. 추가 구현·push·PR은 중지하고 정정된 #3693 계획 승인 지점으로 돌아간다.
7. #3693의 승인된 단계 완료 후 #3695를 같은 방식으로 재개한다.

## 4. 재발 방지 원칙

- 상위 순서 승인은 개별 계획 승인과 같지 않다.
- 계획 문서에는 실제로 검토받은 승인만 기록한다.
- 이미 구현 draft가 있어도 계획 승인 전에는 채택하거나 추가 수정하지 않는다.
- 승인 누락은 사후 승인으로 꾸미지 않고 WIP 보존 → 절차 기록 → 계획 재승인 순으로 복구한다.
- GitHub native parent/sub-issue와 본문 상호 참조를 함께 유지한다.
